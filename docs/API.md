# API reference

The back end is a [Serverpod](https://serverpod.dev) server (see [SERVERPOD.md](SERVERPOD.md)). Every endpoint method is an HTTP call:

```http
POST https://football.api.serverpod.space/<endpoint>/<method>
Authorization: Bearer <access token>
Content-Type: application/json

{ "argumentName": value, ... }
```

- The body is a JSON object of **named arguments**; a method without arguments takes `{}`.
- The response is the JSON of the return type (a model, a list, `null`, or nothing for `void`).
- Failures come back as an error whose message is shown to the player (`GameException`). Authentication failures return HTTP 401; the web client refreshes the token once and retries.
- All endpoints require a signed-in user **unless marked public**. Most also require a profile (a display name) and refuse suspended accounts.
- `UuidValue` arguments and results are UUID strings. Users are identified by their auth user id (a string).
- Local development base URL: `http://localhost:8080`.

The TypeScript wrappers are in [`src/client/api/`](../src/client/api): `http.ts` (transport, token refresh), `session.ts`, `tournament.ts`, `friend.ts`, `social.ts`, `queries.ts` (React Query hooks).

Exact argument names are those of Serverpod's generated client (`football_client`). Access tokens last 10 minutes.

## tournament

The solo World Cup. See [GAMEPLAY.md](GAMEPLAY.md#solo-world-cup) for the format.

| Method | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `current` | — | `TournamentView?` | The caller's latest run: `tournament`, all `fixtures`, group `standings`, `nextFixtureId`, `matchday` |
| `start` | `nationId` | `TournamentView` | Only one run may be in progress; creates all 72 group fixtures |
| `abandon` | — | — | Drops the run in progress |
| `submitResult` | `tournamentId`, `fixtureId`, `nonce`, `homeScore`, `awayScore`, `homePens?`, `awayPens?` | `TournamentView` | Saves the game just played. Scores are integers 0–30. Group stage: the other games of that matchday are simulated. Knockouts: a level game needs shootout goals; the rest of the round is simulated and the next round is drawn. Re-sending the same `nonce` returns the saved state (safe retries) |

## lobby

A room that two players share before the match.

| Method | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `create` | `clientVersion` | `LobbyView` | Caller is the host; closes their older open rooms; refused in maintenance mode. 6 per minute |
| `join` | `code`, `clientVersion` | `LobbyView` | Caller is the guest. Refused if the room is full or closed, the build id differs, or either player has blocked the other. 20 per minute |
| `get` | `lobbyId` | `LobbyView` | Polled about once a second while in a room |
| `setNation` | `lobbyId`, `nationId` | `LobbyView` | The two players must pick different nations; changing a pick clears "ready" |
| `setReady` | `lobbyId`, `ready` | `LobbyView` | When both are ready the `FriendMatch` row is created and `lobby.matchId` is set |
| `leave` | `lobbyId` | — | A host leaving closes the room; a guest leaving frees the seat |
| `rematch` | `lobbyId`, `clientVersion` | `LobbyView` | From a finished match: a fresh room with host and guest swapped and nations kept. Whoever asks first creates it; the other gets the same room |

`LobbyView` = `{ lobby, hostName, hostAvatar?, guestName?, guestAvatar?, youAreHost }`. Lobby `status` is `open`, `live` or `closed`; an open room idle for 3 hours reads as closed.

## friendMatch

The match itself: the WebRTC handshake, how it is connected, leaving, and the signed result. Only the two players of the match can call these.

| Method | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `get` | `matchId` | `MatchView` | `{ match, hostName, guestName, youAreHost }`; also polled during play (about every 3 s) so a leave is noticed even if the data channel is silent |
| `postOffer` | `matchId`, `sdp` | — | Host's WebRTC offer, all ICE candidates already inside (≤ 64 KB) |
| `postAnswer` | `matchId`, `sdp` | — | Guest's answer |
| `getSignal` | `matchId` | `SignalView` | Polled by both peers until the handshake completes |
| `connected` | `matchId`, `transport` | — | `direct` or `relay`; clears the handshake data |
| `leave` | `matchId` | `MatchView` | Walk out of a live match: it ends **immediately** as `abandoned`, recording the caller as the leaver, so the opponent is told at once. A player who already signed full time is not treated as leaving. Also sent with `fetch keepalive` when a tab closes |
| `claim` | `matchId`, `hostGoals`, `guestGoals`, `reason`, `stats?` | `MatchView` | Signs the result as the caller sees it. `reason` is `fulltime` or `abandoned`. `stats` (JSON) is accepted from the host only. Posting the same claim twice is fine. 20 per minute |
| `history` | `limit` | `MatchView[]` | The caller's recent matches, newest first |

Match `status`: `live`, `finished`, `abandoned`, `void`. Resolution rules are in [SERVERPOD.md §8](SERVERPOD.md#8-rules-the-server-enforces) and [MULTIPLAYER.md](MULTIPLAYER.md#signed-results).

## WebSocket relay

Not a Serverpod endpoint but a web-server route: `wss://football.serverpod.space/relay/<matchId>`.

1. Connect, then within 8 s send one text frame: `{"token": "<access token>"}`.
2. Only the host and guest of a **live** match are admitted (close code `4003` otherwise, `4008` on the authentication timeout).
3. Every further text frame (≤ 64 KB) is forwarded unchanged to the other player. The server pings every 20 s.

The frames themselves are the game's own protocol, described in [MULTIPLAYER.md](MULTIPLAYER.md).
