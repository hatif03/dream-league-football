# API reference

The back end is a [Serverpod](https://serverpod.dev) server (see [SERVERPOD.md](SERVERPOD.md)). Every endpoint method is an HTTP call:

```http
POST https://football.api.serverpod.space/<endpoint>/<method>
Authorization: Bearer <access token>
Content-Type: application/json

{ "argumentName": value, ... }
```

- The body is a JSON object of **named arguments**; a method without arguments takes `{}`.
- The response is the JSON of the return type (a model, a list, `null`, or nothing for `void`).
- Failures come back as an error whose message is shown to the player (`GameException`). Authentication failures return HTTP 401; the web client refreshes the token once and retries.
- All endpoints require a signed-in user **unless marked public**. Most also require a profile (a display name) and refuse suspended accounts.
- `UuidValue` arguments and results are UUID strings. Users are identified by their auth user id (a string).
- Local development base URL: `http://localhost:8080`.

The TypeScript wrappers are in [`src/client/api/`](../src/client/api): `http.ts` (transport, token refresh), `session.ts`, `tournament.ts`, `friend.ts`, `duel.ts` (matchmaking, penalty duel, daily challenge, sharing), `social.ts`, `rankings.ts`, `queries.ts` (React Query hooks). The live socket is `src/client/net/live.ts`.

## tournament

| Method | Arguments | Returns | Notes |

## lobby

A room that two players share before the match.

| Method | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `create` | `clientVersion`, `mode?` | `LobbyView` | Caller is the host; `mode` is `match` (default) or `penalties` (a duel refereed by the server); closes their older open rooms; refused in maintenance mode. 6 per minute |
| `join` | `code`, `clientVersion` | `LobbyView` | Caller is the guest. Refused if the room is full or closed, the build id differs, or either player has blocked the other. 20 per minute |
| `get` | `lobbyId` | `LobbyView` | Refetched when the server pushes a `lobby` event; a slow poll (1 s without the live socket, 8 s with it) is the fallback |
| `setNation` | `lobbyId`, `nationId` | `LobbyView` | The two players must pick different nations; changing a pick clears "ready" |
| `setReady` | `lobbyId`, `ready` | `LobbyView` | When both are ready the `FriendMatch` row is created and `lobby.matchId` is set (for a duel, kick 0 is opened in the same transaction) |
| `leave` | `lobbyId` | — | A host leaving closes the room; a guest leaving frees the seat |
| `rematch` | `lobbyId`, `clientVersion` | `LobbyView` | From a finished match: a fresh room with host and guest swapped and nations kept. Whoever asks first creates it; the other gets the same room |

`LobbyView` = `{ lobby, hostName, hostAvatar?, guestName?, guestAvatar?, youAreHost }`. Lobby `status` is `open`, `live` or `closed`; an open room idle for 3 hours reads as closed. `lobby.mode` and `match.mode` are `match` or `penalties`.

## friendMatch

The match itself: the WebRTC handshake, how it is connected, leaving, and the signed result. Only the two players of the match can call these.

| Method | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `get` | `matchId` | `MatchView` | `{ match, hostName, guestName, youAreHost, ratingDelta? }` (`ratingDelta` is the caller's rating change once finished); also polled during play (about every 3 s) so a leave is noticed even if the data channel is silent |
| `postOffer` | `matchId`, `sdp` | — | Host's WebRTC offer, all ICE candidates already inside (≤ 64 KB) |
| `postAnswer` | `matchId`, `sdp` | — | Guest's answer |
| `getSignal` | `matchId` | `SignalView` | Polled by both peers until the handshake completes |
| `connected` | `matchId`, `transport` | — | `direct` or `relay`; clears the handshake data |
| `leave` | `matchId` | `MatchView` | Walk out of a live match: it ends **immediately** as `abandoned`, recording the caller as the leaver, so the opponent is told at once. A player who already signed full time is not treated as leaving. Also sent with `fetch keepalive` when a tab closes |
| `claim` | `matchId`, `hostGoals`, `guestGoals`, `reason`, `stats?` | `MatchView` | Signs the result as the caller sees it. `reason` is `fulltime` or `abandoned`. `stats` (JSON) is accepted from the host only. Posting the same claim twice is fine. Refused for penalty duels (the server decides). When the match finishes, Elo is applied in the same transaction. 20 per minute |
| `history` | `limit` | `MatchView[]` | The caller's recent matches, newest first |

Match `status`: `live`, `finished`, `abandoned`, `void`. Resolution rules are in [SERVERPOD.md §13](SERVERPOD.md#13-rules-the-server-enforces) and [MULTIPLAYER.md](MULTIPLAYER.md#signed-results).

## penalty

The server-refereed penalty duel (only the two players of a `penalties` match may call these). See [MULTIPLAYER.md](MULTIPLAYER.md#the-penalty-duel).

| Method | Arguments | Returns | Notes |
| --- | --- | --- | --- |
| `state` | `matchId` | `DuelView` | `{ matchId, status, youAreHost, hostName, guestName, hostGoals, guestGoals, kicks[], seq, youShoot, youSubmitted, msLeft, youWon?, ratingDelta? }`. `kicks[]` holds `{ seq, shooterIsHost, shooterZone?, keeperZone?, outcome? }`; zones and outcome appear only once a kick is settled. ## Web-server routes

Not endpoints, but routes on Serverpod's web server (the host that serves the app: `https://football.serverpod.space`).

| Route | What it is |
| --- | --- |
| `GET /r/<id>` | A shared result: an HTML page with Open Graph and Twitter-card tags (the picture from cloud storage as `og:image`) and a button into the game. Unknown ids open the app |
| `WS /live` | The live push channel. Send `{"token": "<access token>"}` within 8 s; the server answers `{"live":"ok"}` and then sends `{"t": "<topic>", "id"?: "<room or match id>"}` when something changes: topics `friends`, `lobby`, `chat`, `match`, `duel`, `queue`. Refetch the thing named; messages carry no data. Close `4003` = refused, `4008` = no token in time |
| `WS /relay/<matchId>` | The match relay, below |

## WebSocket relay

Not a Serverpod endpoint but a web-server route: `wss://football.serverpod.space/relay/<matchId>`.

1. Connect, then within 8 s send one text frame: `{"token": "<access token>"}`.
2. Only the host and guest of a **live** match are admitted (close code `4003` otherwise, `4008` on the authentication timeout).
3. Every further text frame (≤ 64 KB) is forwarded unchanged to the other player. The server pings every 20 s.

The frames themselves are the game's own protocol, described in [MULTIPLAYER.md](MULTIPLAYER.md).
